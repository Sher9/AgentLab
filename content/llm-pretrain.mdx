# 预训练基础：从语料到基座模型

你手里的 GPT / Claude / Llama，本质上都是『预训练出来的』。预训练是让模型从无标注文本里学会『语言规律 + 世界知识』的过程，产出的叫**基座模型（base model）**。这一篇不堆公式，只把工程上最该懂的三件事讲透：**喂什么数据、学什么目标、规模怎么影响能力**，并厘清它和微调的关系。

<Callout type="note" title="本篇定位">
  预训练是『重资源、重工程』的环节，绝大多数团队不会从零预训练，而是基于开源基座做微调（见 llm-finetune）。
  所以本篇以概念与决策为主，训练循环用伪代码骨架呈现，真实超参以官方文档为准。
</Callout>

## 1. 预训练到底在做什么

一句话：**给定前面一堆 token，预测下一个 token**。模型在海量文本上反复做这件事，逐渐内化语法、事实、推理模式。它不直接『理解』，而是学到『统计上最合理的续写』——这正是后面所有能力（对话、推理、工具调用）的地基。

预训练产出的基座模型有两个特征，新手常踩坑：

- 它是『续写机器』，**不会**听话地回答问题。你给它『法国的首都是』，它大概率续出『巴黎』，但给它『请回答：法国的首都是？』，它可能继续编故事——因为它没被教过『按指令作答』。
- 它天然有『下一词预测』倾向，需要**微调 / 对齐**（SFT、RLHF）才能变成可用的助手。

<Callout type="warn" title="别直接拿基座模型当产品">
  很多团队第一次下载 Llama 基座后，发现它『答非所问』就以为是模型不行。其实基座本就该续写，
  对齐（指令微调）是单独一步。把 base 模型当聊天模型用，是预训练认知的第一课。
</Callout>

## 2. 数据：预训练的燃料

数据质量直接决定模型上限。工程上关注四个维度：

### 2.1 数据来源

- **网页文本**：Common Crawl 衍生的 C4、RefinedWeb、FineWeb 等，量大但噪声多，需清洗。
- **书籍 / 百科**：BookCorpus、Wikipedia，质量高、长程依赖好。
- **代码**：GitHub 语料（The Stack），提升推理与结构能力。
- **学术 / 专业**：arXiv、PubMed，强化垂直领域知识。

### 2.2 去重与清洗

重复数据会让模型『死记』而非泛化。常规操作：

- **精确去重**：按文档哈希去掉完全重复。
- **近似去重**：MinHash + LSH 去掉高度相似文档（这是工业级流水线的标配）。
- **质量过滤**：用分类器 / 启发式规则剔除低质（乱码、导航栏、垃圾 SEO）。
- **毒性与隐私过滤**：去个人身份信息（PII）、降毒性内容。

<Callout type="tip" title="数据规模的数量级">
  Llama 2 训练语料约 2T tokens；现代前沿模型普遍在数 T 到十数 T tokens。
  但对垂直场景，几百万到几十亿高质量 tokens 的继续预训练（continued pretraining）就常有收益。
</Callout>

### 2.3 数据配比

不同来源的比例不是拍脑袋：代码占比高→推理强；多语料→跨语言能力好。配比实验是预训练里最烧钱也最关键的『玄学』环节之一。

## 3. 目标函数：模型到底在优化什么

主流采用**因果语言建模（Causal Language Modeling, CLM）**：

```
输入序列:  [x₁, x₂, x₃, ..., xₙ]
目标:      预测 x₂|x₁,  x₃|x₁x₂,  ...,  xₙ|x₁..xₙ₋₁
损失:      每个位置的交叉熵之和取平均
```

模型一次看到整个序列（靠注意力掩码保证第 i 个位置只能看到前 i 个 token），但只在『预测下一个』上算损失。这种『自监督』无需人工标注，所以能吃到互联网级数据。

<Callout type="note" title="为什么是因果而非掩码">
  BERT 用的掩码语言建模（MLM，预测被遮住的词）适合理解类任务；
  而 GPT 系的因果 LM 适合生成。现代生成式大模型几乎清一色选因果 LM，因为它天然适配『续写 / 对话 / 推理链』。
</Callout>

### 3.1 训练循环伪代码骨架

下面是一段**概念级**训练循环（不可直接运行，真实实现见 PyTorch + Transformers / Megatron，以官方文档为准）：

```python
# pretrain_loop.py —— 预训练主循环（思路骨架，非可运行生产代码）
# 以官方文档为准：实际分布式训练涉及 FSDP/DeepSpeed、梯度累积、混合精度等

for batch in dataloader:            # batch = 一堆 token 序列 [B, T]
    logits = model(batch.input_ids) # 前向：输出每个位置的词表分布 [B, T, V]
    # 因果 LM：用『错位』的目标——输入 x，预测 x 的下一个
    loss = cross_entropy(
        logits[:, :-1, :],          # 预测侧：位置 1..T-1
        batch.input_ids[:, 1:],     # 目标侧：位置 2..T（即下一个 token）
    )
    loss.backward()                 # 反向传播，算出每个参数梯度
    optimizer.step()                # 沿梯度更新参数
    optimizer.zero_grad()           # 清空梯度，准备下一批
```

要点：**目标错位一行**（`input_ids[:, 1:]`）就是因果 LM 的全部秘密——模型永远在『用前文的表示，去猜后一个词』。

## 4. 规模定律：能力随规模涌现

**Scaling Laws（规模定律）** 指出：在足够大的范围内，模型的**测试损失**随参数量、数据量、算力的增加而**可预测地下降**，近似幂律关系。工程含义很硬：

- 想让损失降一点，参数量 / 数据量可能要翻几倍——这是个『烧钱换能力』的权衡。
- **三者要匹配**：盲目堆参数但数据不够 → 过拟合；数据堆满但参数太小 → 学不下。经验法则是『参数 : 数据 tokens』大致 1:10 到 1:20。

<Callout type="warn" title="规模定律不是万能保险">
  损失下降 ≠ 任务能力线性提升。很多『能力涌现』（如复杂推理）在规模跨过阈值后才明显，
  但也可能只是评测指标非线性造成的观感。把它当『预算规划工具』，而非『能力保证书』。
</Callout>

## 5. 预训练 vs 微调：边界在哪

这是本篇最核心的一张表，决定你该往哪投资源：

| 维度 | 预训练（Pretraining） | 微调（Fine-tuning，见 llm-finetune） |
|------|----------------------|--------------------------------------|
| 数据 | 海量无标注文本（T 级 tokens） | 高质量有标注样本（千～百万级） |
| 目标 | 通用语言/知识建模（CLM） | 适配特定任务/风格/格式 |
| 成本 | 极高（千卡×天～月） | 低到中（单卡～几卡×小时） |
| 产出 | 基座模型 base | 指令模型 / 领域模型 |
| 谁来做 | 大厂 / 顶级实验室 | 普通团队也可行 |
| 是否需对齐 | 否（产出续写器） | 是（SFT/RLHF 让其听话） |

<Callout type="tip" title="决策树">
  问自己：是要『造一个新模型』，还是『让现成模型更懂我的业务』？
  99% 的团队答案是后者——直接基于开源基座做 SFT / LoRA，别碰全量预训练。
  只有当领域语料极度特殊（如罕见语种、专有化学符号）且现成模型完全空白时，才考虑继续预训练。
</Callout>

## 6. 常见坑

<Callout type="danger" title="数据泄漏">
  评测集（如公开基准）若混入训练语料，指标会虚高、上线即翻车。工业流程必须做
  『训练/评测去污染（decontamination）』——用 n-gram 重叠检测并剔除。
</Callout>

<Callout type="warn" title="数据质量 > 数据数量">
  低质冗余数据堆再多，也比不过精心过滤的干净语料。先做去重和质量过滤，再谈规模。
  很多人迷信『数据越多越好』，结果模型学会了复读噪声。
</Callout>

<Callout type="warn" title="继续预训练会冲掉原能力">
  在基座上做领域继续预训练时，若不加『重放（replay）』原分布数据，
  模型可能在学新领域的同时『忘记』通用能力（灾难性遗忘）。务必混训一部分通用数据。
</Callout>

<Callout type="note" title="tokenizer 要配套">
  预训练时选的 tokenizer（词表、BPE 规则）和模型绑定。换 tokenizer 等于换输入空间，
  旧权重无法直接复用。垂直场景若自定义 tokenizer，需从预训练起步或谨慎做 embedding 映射。
</Callout>

## 7. 用 Zod 校验预训练样本格式

虽然预训练本身不是 OpenAI API 调用，但当你**准备 / 验收训练数据**时，可以用 Zod 守住格式关。下面是一段 Node 侧校验 JSONL 样本骨架（沿用 OpenAI SDK 项目的 Zod 习惯）：

```ts
// validate_pretrain_sample.ts —— 校验单条预训练样本结构
import { z } from 'zod';

// 一条预训练样本：明文文本即可（CLM 不需要标注）
const PretrainSample = z.object({
  text: z.string().min(1, '文本不能为空'),
  // 可选元信息：来源域，便于后续配比与去重分析
  domain: z.enum(['web', 'book', 'code', 'academic']).optional(),
});

// 真实场景：逐行读 JSONL，逐条 safeParse，非法行落盘待人工看
function validateLine(line: string): boolean {
  const parsed = PretrainSample.safeParse(JSON.parse(line));
  if (!parsed.success) {
    console.error('坏样本:', parsed.error.message);
    return false;
  }
  return true;
}
```

<Callout type="tip" title="把校验前移">
  数据校验越靠前（采集即校验）成本越低。等到训练跑了一半才发现 5% 样本是乱码，
  烧毁的 GPU 小时是真金白银。Zod 这种轻量校验，建议在入库管线里就挡一道。
</Callout>

## 小结

- 预训练 = 在海量文本上做因果语言建模（预测下一个 token），产出『续写型』基座模型。
- 三支柱：**数据（去重+质量+配比）**、**目标（CLM + 错位一行）**、**规模（Scaling Laws 的幂律权衡）**。
- 预训练与微调是不同量级的不同环节：前者造基座、后者做适配；99% 团队应从微调入手。
- 红线：防数据泄漏、重质量轻数量、继续预训练要防遗忘、tokenizer 与模型绑定、校验前移。
