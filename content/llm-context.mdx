# 长上下文：窗口、缓存与压缩

『上下文窗口』（Context Window）是 LLM 一次能『看到』的最大 token 数。它决定了模型能同时处理多长的对话、多长的文档。本篇讲清窗口背后的机制、位置编码如何被扩展到更长、如何用缓存省成本，以及超长文本该『压』还是『拆』。

## 1. 窗口的本质：不只是 token 数

上下文窗口是 `输入 + 输出` 合起来的总 token 上限。它背后是注意力的代价：

- 自注意力对序列长度是 **O(n²)** 的计算与显存（n 为 token 数）；
- 推理时模型要维护 **KV Cache**（每层的 Key/Value 矩阵），窗口越长，缓存占用越大、越贵。

所以『把窗口做大』不是简单改个数字，而是位置编码、注意力机制、显存多方面的工程问题。

<Callout type="note" title="窗口大≠用得好">
  模型能装下 100k token，不代表它能在 100k 里精准定位关键信息。长上下文存在
  『中间遗忘（lost in the middle）』现象：放在文档中段的事实，模型召回率明显低于
  开头和结尾。窗口够大只是前提，怎么排布信息才是工程重点。
</Callout>

## 2. 位置编码扩展：让模型『看得更远』

原训练模型在固定长度（如 4k）上学会位置感知。要支持更长窗口，不能简单塞更多 token——位置编码会『越界』。主流扩展思路（概念层面，不编造具体 API）：

- **位置插值（Position Interpolation）**：把位置坐标线性压缩进原训练范围，让 32k 的位置映射到原 4k 空间，平滑过渡；
- **NTK-aware 缩放**：更聪明地缩放旋转频率，保留高频细节，比线性插值损伤小；
- **YaRN**：结合插值与外推，兼顾长程与短程，是目前很多长上下文模型的底座思路。

<Callout type="warn" title="扩展有上限">
  位置扩展能『撑大窗口』，但超出训练分布太远，模型在极长位置的推理质量会下降，
  且需要高质量长文本继续训练（Long-Context SFT）来巩固。窗口数字可以标 128k，
  但对齐质量往往不如原生训练的长上下文模型。
</Callout>

## 3. Prompt 缓存：省成本的关键

长上下文里大量内容是**重复**的——系统提示、知识库片段、长文档在多次请求里不变。Prompt 缓存（Prompt Caching）让厂商把这段前缀的 KV Cache 复用，命中缓存的部分**计费大幅降低**、延迟也下降。

- OpenAI、Anthropic 等均已支持前缀缓存（具体开启方式与折扣以官方文档为准）；
- 关键是『把稳定不变的内容放前缀』：系统提示、长文档放最前，变动的用户问题放最后，才能最大化命中。

<Callout type="tip" title="稳定内容放前缀">
  缓存按『前缀匹配』生效。把不变的 system prompt、长文档、工具定义放 messages 最前，
  用户问题放最后。若每次都在前面拼一个随机时间戳，缓存永远不命中。
</Callout>

## 4. 压缩与长文摘要策略

当文档超过窗口，或塞进去太贵，就要『压缩』。两种路线：

### 4.1 检索式（RAG）：只取相关片段

不把全文塞进窗口，而是先把文档切块编码（见 llm-embedding），按 query 语义召回 top-k 注入。这是生产里处理超长文档的**首选**——既省 token，又缓解『中间遗忘』。

### 4.2 摘要式：map-reduce / refine

若必须『理解全文』（如生成长文档的全局摘要），用分治：

- **Map-Reduce**：先把文档切成块，逐块各生成一个局部摘要（map），再把这些摘要合并成全局摘要（reduce）；
- **Refine**：逐块读，不断把新内容 refinement 进一个滚动摘要，省一次大合并但串行较慢。

```ts
// long-summary.ts —— Map-Reduce 长文档摘要骨架（可运行）
import OpenAI from 'openai';
import 'dotenv/config';

const client = new OpenAI();

// 把长文切成约 maxChars 的块（真实场景用语义切分，见 RAG 切分篇）
function chunk(text: string, maxChars = 3000): string[] {
  const out: string[] = [];
  for (let i = 0; i < text.length; i += maxChars) out.push(text.slice(i, i + maxChars));
  return out;
}

// map：每块各生成局部摘要
async function mapChunk(c: string): Promise<string> {
  const r = await client.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: '用 2 句话概括下面这段的核心信息。' },
      { role: 'user', content: c },
    ],
  });
  return r.choices[0].message.content ?? '';
}

// reduce：把局部摘要合并成全局摘要
async function reduce(summaries: string[]): Promise<string> {
  const r = await client.chat.completions.create({
    model: 'gpt-4o-mini',
    messages: [
      { role: 'system', content: '根据以下分段摘要，输出一份连贯的全局摘要。' },
      { role: 'user', content: summaries.join('\n---\n') },
    ],
  });
  return r.choices[0].message.content ?? '';
}

async function summarize(longText: string): Promise<string> {
  const chunks = chunk(longText);
  const parts = await Promise.all(chunks.map(mapChunk)); // 各块可并行，省时延
  return reduce(parts);
}
```

<Callout type="warn" title="map-reduce 会丢细节">
  逐块摘要必然损失块内细节，合并时也可能前后矛盾。若任务要求『不漏关键数字/条款』，
  摘要式不如检索式稳。需要精确时，优先 RAG 召回原文片段，而非喂摘要。
</Callout>

## 5. 对比：三种长文本处理路线

| 路线 | 做法 | 优点 | 缺点 | 适用 |
|------|------|------|------|------|
| 直接塞窗口 | 全文进 prompt | 简单、保细节 | 贵、超窗口报错、中间遗忘 | 中短文档、需全文理解 |
| RAG 检索 | 切块召回 top-k | 省 token、可扩展、抗遗忘 | 需检索质量支撑 | 超长文档、知识问答 |
| 摘要压缩 | map-reduce/refine | 出全局概览、省 token | 丢细节、可能矛盾 | 长文概览、报告生成 |

## 6. 踩坑

<Callout type="danger" title="超窗口直接 400">
  输入+输出超过模型上限会直接报错。上线前必须估算最大输入（长文档+历史+系统提示），
  超阈值就走 RAG 或摘要，不要无脑堆叠。给输出也留足余量。
</Callout>

<Callout type="warn" title="缓存命中被破坏">
  在稳定前缀里插入变动内容（时间戳、随机 id、每轮变化的统计），会让前缀缓存失效，
  成本与延迟双双回升。把『会变的东西』统一放最后。
</Callout>

<Callout type="warn" title="中间遗忘导致答非所问">
  关键信息放文档中段，模型容易忽略。重要指令/事实尽量放开头或结尾；
  或改用 RAG 把相关片段直接贴近问题注入，缩短模型需扫描的距离。
</Callout>

<Callout type="warn" title="窗口大不代表能推理长程依赖">
  即使装得下，模型对超长序列里『首尾呼应』『跨段计数』等长程推理仍易出错。
  这类任务别迷信窗口长度，应拆成可验证的小步或借助工具（如代码计算）。
</Callout>

## 小结

- 上下文窗口是输入+输出总上限，背后是 O(n²) 注意力与 KV Cache 成本。
- RoPE 扩展（插值/NTK/YaRN）让模型看得更远，但超出训练分布质量会降，需长上下文 SFT 巩固。
- Prompt 缓存按前缀命中省成本：稳定内容（system/文档）放最前，变动内容放最后。
- 超长文本三选一：直接塞窗口（中短、保细节）、RAG 检索（超长、首选）、摘要压缩（概览）。
- 红线：超窗口必 400、缓存前缀别插变动、警惕中间遗忘、长程推理别迷信窗口。
